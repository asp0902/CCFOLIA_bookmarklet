## 0. 사전 확인 (먼저 읽기)

- [ ] **GitHub Pages 반영 여부.** 확장의 `relay-page.js`는 `window.__CCF_SECOND_CHAT_PANEL__.relayMessages()` / `.relaySend()`를 호출합니다. 이 함수들은 확장 파일이 아니라 GitHub Pages 로더가 불러오는 `legacy/ccfolia-chat-panel.user.js`에 있고, 이 변경은 PR #113에만 있습니다. PR이 머지되어 Pages에 배포되기 전에는 옛 스크립트가 로드되어 **채팅 중계(양방향)가 동작하지 않을 수 있습니다.**
  - 확인: 룸 탭 DevTools 콘솔에서 `typeof window.__CCF_SECOND_CHAT_PANEL__?.relaySend` 가 `"function"` 이면 진행, `"undefined"` 면 아래 중 하나를 선택합니다.
    - (a) PR을 머지/배포한 뒤 진행한다.
    - (b) 4장·5장(채팅)은 보류하고 1~3장, 6~7장만 검증한다.
- [ ] 테스트룸에 지금 대화 기록이 남아도 괜찮은지 확인합니다. 참여자 발언은 **GM 본인 계정 이름**으로 `[참여자 웹 · 이름]` 접두사가 붙어 기록됩니다.
- [ ] 브라우저 2개를 준비합니다: GM용 Chrome(확장 설치) / 참여자용(다른 브라우저 또는 시크릿 창 + 휴대폰 1대).

## 1. 코코포리아 로그인 (GM 계정)

1. Chrome에서 `https://ccfolia.com/` 접속 후 테스트룸의 GM(룸 주인) 계정으로 코코포리아에 로그인합니다. (3장의 GM 토큰과는 별개입니다.)
2. `https://ccfolia.com/rooms/ChW_QP77I` 를 열어 룸이 정상적으로 보이는지 확인합니다.

- [ ] 로그인 성공, 테스트룸 진입 가능

## 2. 확장 프로그램 설치 (PR 브랜치 기준)

1. PR 브랜치를 로컬에 받습니다.
   `git fetch origin claude/ccfolia-bookmarklet-player-room-rz0gi1`
   `git checkout claude/ccfolia-bookmarklet-player-room-rz0gi1`
2. Chrome에서 `chrome://extensions` 를 엽니다.
3. 오른쪽 위 **개발자 모드**를 켭니다.
4. **압축해제된 확장 프로그램을 로드합니다** → 저장소의 `extension/personal` 폴더를 선택합니다. (이미 설치돼 있으면 **새로고침** 아이콘)
5. 버전이 `1.2.0` 인지 확인하고, 확장 아이콘을 툴바에 고정합니다.
6. 테스트룸 탭을 새로고침합니다.

- [ ] 확장 로드 성공(오류 배지 없음, `chrome://extensions` 의 "오류" 버튼 없음)
- [ ] 룸에서 카피바라 툴킷이 자동 실행됨
- [ ] 요청 권한이 `scripting`, `storage` 와 호스트 3개(ccfolia.com, 127.0.0.1:8787, workers.dev)뿐

## 3. 확장 옵션 설정

1. 확장 우클릭 → **옵션** 을 엽니다.
2. **로컬 릴레이 공유 사용** 체크.
3. **릴레이 주소**: `https://capybara-public-handout-relay.for-trpg.workers.dev` (기본값은 로컬 `127.0.0.1:8787` 이므로 반드시 바꿉니다)
4. **GM 토큰**: 배포 때 설정한 `GM_TOKEN` 값을 직접 입력 → **저장**.
5. 테스트룸 탭을 새로고침합니다.

- [ ] 저장 시 오류 없음
- [ ] 새로고침 후 옵션의 **참여자 초대 URL** 에 값이 생김 (자동 `connect` 성공)
- [ ] 옵션의 룸 표시가 `ChW_QP77I` 계열로 바뀜

## 4. 참가와 승인

1. 참여자 브라우저에서 초대 URL을 엽니다.
2. 표시 이름 입력, 동의 체크, **참가 요청**.
3. GM 옵션 페이지 **참가 승인** 에서 **새로고침** → 해당 참여자가 `pending` 으로 보임.

- [ ] 승인 전: 참여자 화면이 대기 상태이고 룸 내용/채팅이 보이지 않음
- [ ] **거절** 시: 참여자가 룸 정보를 받지 못함 (거절용 두 번째 참여자로 확인)
- [ ] **승인** 시: 참여자 화면이 플레이 화면으로 전환됨
- [ ] 표시 이름에 `<b>x</b>` 같은 HTML을 넣어도 그대로 텍스트로 표시됨

## 5. 채팅 양방향 (0장 (a) 충족 시)

- [ ] CCFOLIA에서 GM이 보낸 메인 채널 메시지가 참여자 화면에 나타남 (1~3초 이내)
- [ ] 참여자가 보낸 메시지가 CCFOLIA 메인 채널에 `[참여자 웹 · 이름]` 접두사로 한 번만 기록됨
- [ ] 참여자 화면에서 전송 후 상태 표시가 정상(실패 메시지 없음)
- [ ] 같은 메시지가 CCFOLIA 쪽에 중복 기록되지 않음
- [ ] 참여자 메시지가 다시 참여자 화면으로 되돌아올 때 중복 표시되지 않음
- [ ] 2000자 초과 입력은 잘리거나 거부되고 오류 없이 동작함
- [ ] 다른 채널/비밀 대화/GM 메모가 참여자에게 보이지 않음 (메인 채널만)

## 6. 재연결과 중복 방지

- [ ] 참여자 화면 새로고침 후 승인 상태와 채팅 기록 유지
- [ ] GM 룸 탭 새로고침 후 자동 재연결, 이미 전달된 참여자 메시지가 **다시 기록되지 않음**
- [ ] GM 탭을 닫은 상태에서 참여자가 메시지 전송 → 참여자 화면에 "GM 연결" 상태가 끊김으로 표시 → GM 탭을 다시 열면 대기 중 메시지가 **한 번만** 전달됨
- [ ] 확장을 끄고(옵션에서 사용 해제) 참여자 전송 시 CCFOLIA에 기록되지 않음

## 7. 공개 핸드아웃과 중지

- [ ] 핸드아웃 카드의 **참여자 웹에 공개 내용 공유** 로 공유하면 참여자 화면에 제목/본문이 plain text로 표시됨
- [ ] `gmNotes` 등 비공개 필드가 참여자에게 노출되지 않음
- [ ] **접근 취소**(revoke): 해당 참여자의 이후 `/state`, `/messages` 요청이 막히고 화면이 접근 불가 상태가 됨
- [ ] **공유 중지**: 모든 참여자 연결이 끊기고 새로고침 후에도 들어갈 수 없음
- [ ] 중지 후 이전 초대 URL로 재참가가 불가함
